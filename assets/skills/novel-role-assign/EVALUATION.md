# 内置小说 skill 评测标准

## 对象与版本

评测原文片段的类别、人物归属，以及音色/语气建议的约束。每次记录 skill name/version/SHA-256、模型、连接协议、分段版本、参数、样本正文 SHA-256、usage 与阶段耗时。凭据不进入报告。

首版 `1.0.0` 提取此前代码中的五段提示词，运行时继续使用原有 Schema 和有界状态机。旧捕获没有 skill 指纹，必须标为 legacy/unversioned；离线回放可记录当前处理版本，不能把它当成新 skill 的一次真实推理。

## 不变量：任一失败都阻止验收

- 原文与稳定片段 ID 不被模型改写；UTF-16 输出完整覆盖原文，不重叠、不漏段、不拆开代理对。
- 人工锁定和当前正文版本的人工确认不被 AI 覆盖；不同作品的人物/音色不能混用。
- 标签 ID、类别、人物、音色及证据符合 Schema 与作用域；重复、缺失、未知标签不部分写入。
- 暂停、取消和预算耗尽保留可恢复进度。skill 内容变化或旧检查点无指纹时，要求明确重启分析。
- 音色/语气只给候选，人工选择应用；正文、声音或 skill 变化后拒绝旧建议。
- 401/429、超时、断连、截断输出是失败状态，不计为准确率，也不等同模型不支持。

## 数据与评分

已有 12 组回归样本在 `scripts/tests/fixtures/role_assign/`，保留上游 NOTICE/LICENSE。金标和人工名称对应表只供评分，不进入模型输入。

- 类别正确率：命中允许类别的金标数 / 可评分类别金标数。
- 人物正确率：类别正确且人物命中的金标数 / 含人物要求的可评分金标数。
- 备选类别、备选人物表示允许多个合理答案，每条金标仍只计一次；无法唯一定位的金标单列排除。
- 严格匹配使用金标规范名及已有别名。人工名称对齐另出一份报告和对应依据；不得靠对齐更正真正误分。
- 缺失预测、失败样本、未匹配金标和未完成运行必须单列，不计为通过。

2026-11-17 既有 gpt-6-luna 捕获基线（提取前，未版本化）：类别 245/249（98.4%）；修复后人物严格 200/240（83.3%）；人工明确同人名称对齐后 219/240（91.3%）。这组数字是回归参考，不是所有小说的准确性保证，也不是新 skill 的独立实测。

## 候选版本比较

1. 已看过的 12 组作为回归集；另加未见的长章节、群聊、匿名路人、第一人称、传音、嵌套讲述、跨章身份揭晓作为留出集。
2. 固定模型、协议、分段、预算和评分口径，每个候选与基线至少各跑 3 次；金标不得传给模型。付费运行须显式启动。
3. 同时比较严格/名称对齐分数、角色召回与重复身份、运行间一致率、失败率、延迟和 tokens。不能只报告最好的一次。
4. Reviewer 另算疑点精确率/召回率、改对数、改坏数、净收益与每次修复成本。当前离线评分器只实现类别/人物评分；这些决策收益指标尚待加入工具。
5. 候选须通过全部不变量；准确率和稳定性不低于同条件基线，且至少一项目标指标改善。任何退化或成本上升应注明原因，交由维护者决定是否接受；不得自动发布。

## 运行

均从仓库根目录执行：

```powershell
flutter test scripts/tests
pwsh -File scripts/tools/test_novel_roles.ps1 -Model gpt-6-luna -OutputDirectory .dart_tool/role-skill-candidate
dart scripts/tools/evaluate_role_assignments.dart .dart_tool/role-skill-candidate .dart_tool/role-skill-candidate/strict.md
```

本地回放使用 `-Replay` 和已有捕获目录，不访问推理服务。回放能验证解析、存储和约束，不能验证模型面对改动后的提示词会如何回答。
