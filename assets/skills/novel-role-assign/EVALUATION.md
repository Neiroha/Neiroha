# 内置小说 skill 评测标准

## 对象与版本

评测原文片段的类别、人物归属，以及音色/语气建议的约束。每次记录 skill name/version/SHA-256、模型、连接协议、分段版本、参数、样本正文 SHA-256、usage 与阶段耗时。凭据不进入报告。

首版 `1.0.0` 提取此前代码中的五段提示词，运行时继续使用原有 Schema 和有界状态机。旧捕获没有 skill 指纹，必须标为 legacy/unversioned；离线回放可记录当前处理版本，不能把它当成新 skill 的一次真实推理。

`1.1.0` 与 semantic-v2、结构化场景和独立疑点复核一起评测，不能将整体差异分离归因到某一段提示词。新增短留出集位于 `scripts/tests/fixtures/role_holdout/`；运行器与评分器用 `--fixtures` 选择，原有十二组仍作为回归集。需要继续增加长章节与更多题材。

`1.2.0` 新增第六个提示阶段 `tool_reviewer`：独立按需运行，模型通过严格结构化 action envelope 让应用调度本地工具，支持 Chat Completions/Responses；不是要求网关实现原生 function calling。每轮 3 次调用/20,000 token 预算/6 次读取/8 条提案，单次输出上限 1,600 tokens。未知 usage 保留调用前的 UTF-8 字节+schema+输出上限+512 保守预留；有正整数 usage 才对账，超预算停止。它是预算控制，不能替代服务商账单或保证异常服务商的计费上限。

`1.3.0` 将重规划独立为第七段提示词，补充规范名、匿名第一人称、跨媒介、台本、多语言、听者与引语层级规则；新增全局多配置、阶段覆盖及一键恢复，小说与长文本共用。旧提示包缺少 replanner 时可回落 planner 供受控基线比较，打包默认值始终包含七段。当前覆盖值与配置 ID 进入有效指纹，修改后拒绝旧检查点/提案。

本轮参考用户指定的 [CosyVoiceDesktop dev 快照 df564890](https://github.com/Moeary/CosyVoiceDesktop/tree/df564890eb1cffb42bd87ab7cd2c2aa1f13e9ad0/core/role_agent)。旧项目技能为 2.3；其“叙述者读所有嵌套引用”与本仓库部分留出金标的“内层人物读直接引语”有策略差别，因此增加用户配音意图实测，严格分数保留策略差异。没有引入 Python/LangGraph 运行时；Dart 节点保留程序层权限与验证。

## 不变量：任一失败都阻止验收

- 原文与稳定片段 ID 不被模型改写；UTF-16 输出完整覆盖原文，不重叠、不漏段、不拆开代理对。
- 人工锁定和当前正文版本的人工确认不被 AI 覆盖；不同作品的人物/音色不能混用。
- 标签 ID、类别、人物、音色及证据符合 Schema 与作用域；重复、缺失、未知标签不部分写入。
- 暂停、取消和预算耗尽保留可恢复进度。skill 内容变化或旧检查点无指纹时，要求明确重启分析。
- 音色/语气只给候选，人工选择应用；正文、声音或 skill 变化后拒绝旧建议。
- 401/429、超时、断连、截断输出是失败状态，不计为准确率，也不等同模型不支持。

## 数据与评分

已有 12 组回归样本在 `scripts/tests/fixtures/role_assign/`，保留上游 NOTICE/LICENSE。金标和人工名称对应表只供评分，不进入模型输入。

- 类别正确率：命中允许类别的金标数 / 可评分类别金标数。
- 人物正确率：类别正确且人物命中的金标数 / 含人物要求的可评分金标数。
- 备选类别、备选人物表示允许多个合理答案，每条金标仍只计一次；无法唯一定位的金标单列排除。
- 严格匹配使用金标规范名及已有别名。人工名称对齐另出一份报告和对应依据；不得靠对齐更正真正误分。
- 缺失预测、失败样本、未匹配金标和未完成运行必须单列，不计为通过。

2026-11-17 既有 gpt-6-luna 捕获基线（提取前，未版本化）：类别 245/249（98.4%）；修复后人物严格 200/240（83.3%）；人工明确同人名称对齐后 219/240（91.3%）。这组数字是回归参考，不是所有小说的准确性保证，也不是新 skill 的独立实测。

## 候选版本比较

1. 已看过的 12 组作为回归集；另加未见的长章节、群聊、匿名路人、第一人称、传音、嵌套讲述、跨章身份揭晓作为留出集。
2. 固定模型、协议、分段、预算和评分口径，每个候选与基线至少各跑 3 次；金标不得传给模型。付费运行须显式启动。
3. 同时比较严格/名称对齐分数、角色召回与重复身份、运行间一致率、失败率、延迟和 tokens。不能只报告最好的一次。
4. Reviewer 另算疑点精确率/召回率、改对数、改坏数、净收益与每次修复成本。`RoleReviewEvaluation` 与 `evaluate_role_review.dart` 已实现这些指标、严格人物召回/重复身份及跨运行一致率；无分母为 null，只有输入至少两轮才比较一致率。只在带金标的范围计算检测指标；手动选择目标的分数不能冒充自动疑点检测器效果。跨轮一致率按同一金标覆盖范围内的边界、类别、人物标签成对比较。
5. 候选须通过全部不变量；准确率和稳定性不低于同条件基线，且至少一项目标指标改善。任何退化或成本上升应注明原因，交由维护者决定是否接受；不得自动发布。

## 运行

均从仓库根目录执行：

```powershell
flutter test scripts/tests
pwsh -File scripts/tools/test_novel_roles.ps1 -Model gpt-6-luna -OutputDirectory .dart_tool/role-skill-candidate
dart scripts/tools/evaluate_role_assignments.dart .dart_tool/role-skill-candidate .dart_tool/role-skill-candidate/strict.md
```

本地回放使用 `-Replay` 和已有捕获目录，不访问推理服务。回放能验证解析、存储和约束，不能验证模型面对改动后的提示词会如何回答。

P1 微型真实测试（默认两组，总上限 6 次/40,000 保守预算 tokens，不自动重试；`--cases merge` 另选单目标、最多 1 次）：

```bash
dart scripts/tools/run_live_tests.dart review --model gpt-6-luna --output .dart_tool/review-candidate
dart scripts/tools/evaluate_role_review.dart .dart_tool/review-candidate/capture.json
```

金标在 `scripts/tests/fixtures/role_review/`，仅用于离线评分。微型用例人为植入错误，用于验证提案链路；不等于全文分角效果对比。运行器拒绝覆盖既有捕获；输出同时保留原始模型响应、usage、技能身份、提案及采纳前后状态。当前 CLI 对内置微型用例评分；领域评分器可接受其他完整 UTF-16 预测与多轮结果。

2026-11-17 实测共 6 次/8,591 tokens：群聊新增人物并改对 2 条，改坏 0 条；另一次单目标合并消除重复身份。原第一组因只传最后两条查询结果而循环查询，3 次预算内无提案，该结果保留；已修复消息组装并用本地回归验证，未额外付费重跑该整组。未做完整多轮/长章节比较，不能宣布 1.2.0 达到候选验收门槛或发布。

## 1.3.0 三轮矩阵

`scripts/tools/run_role_quality.dart` 使用冻结的基线 1.2.0 与候选 1.3.0、21 种文本各三轮，共 126 个计划运行。新增原创金标见 `scripts/tests/fixtures/role_quality/`；原 12 组、先前 3 组留出集原样保留。模型固定 gpt-6-luna、Chat Completions、20 段/批、单次输出上限 4096；所有阶段 usage 与原始输出存盘。`evaluate_role_quality.dart` 离线比较并生成 Markdown/JSON，失败与未配对分母单列，不挑最好一轮。

预算 50 美元由全局持久化账本执行，预跑、失败和意图测试共用；未知 usage 保留预留。已知 usage 的标准估算按输入最高 cache-write 价格与输出单价计算，另保留更保守的 2 美元/百万总 tokens 守门值。[2026-11-17 核对的官方 Luna 价格](https://developers.openai.com/api/docs/models/gpt-6-luna)为每百万输入 $0.10、缓存输入 $0.01、cache-write $0.125、输出 $0.50。该估算不代表账户实际账单或未来价格。

网络恢复可以复用同模型/原文/skill 的成功阶段：先离线还原状态机，再显式继续付费。纯离线回放不会发请求。初始预跑暴露的非阻塞文件锁和匿名第一人称过滤已修复并保留失败记录；对比矩阵共用修复后的运行时，最终报告保留所有尝试成本。不同传输路径和并发会影响延迟，不能将耗时差异全归因提示词。

长文本真实意图检查用相同正文分别指定“现场讲述者读引用”与“广播剧内层角色读直接引语”，另测台本舞台说明。金标只在评分时读取；用户意图是输入条件，不能拿包含答案的金标列表替代它。

最终矩阵 126/126 流程完成、63/63 配对，覆盖 5,532 个语义片段。基线→候选：类别 963/972→967/972（99.1%→99.5%），严格人物 772/933→837/933（82.7%→89.7%），人物召回 87.6%→91.4%，三轮标签一致率 84.7%→91.5%。成功逻辑调用 370→366、tokens 1,248,694→1,291,743（+3.4%）。同文两种意图的引用分别归陈叔/周柏，各 2/2；台本人物 2/2、类别 3/3。

退化与限制：仙侠组三轮人物严格少 5、类别少 2，主要涉及未具名台下评论及表演策略。批次 Reviewer 从改对/改坏 1/2 到 1/1，候选净收益仍为 0；混合送审精确率降低、召回率提高，不把整体提升归因 Reviewer。原始分数不做人工名称对齐，错例见本机 `.dart_tool/role-quality-2026-11-17/errors.md`。开发者新编样本与三轮比较不能替代独立外部盲测或整本小说验收。

本轮计费审计含预跑/失败/意图测试共 989 次请求尝试、已知 3,102,873 tokens，标准价格上界估算 $0.6484。73 次未知 usage 保留预留，更保守的全局账本总占用 $8.1666/$50；不以此冒充账户实际账单。所有真实请求已结束。完整逐轮分数、配对结果、技能快照、原始响应、续跑标记及费用账本保存在本机 `.dart_tool/role-quality-2026-11-17/`，不随 Git 分发。

最终节点路由检查：带配音意图的首次分析使用 planner，只有已存在角色表的反馈任务使用 replanner；用户编辑的初始规划提示词已由本地标记回归验证。该分支不影响无反馈的 126 组矩阵。修正后再次真实检查两种引用意图及台本，三组均通过（各 3 次调用），所有费用计入同一账本。
